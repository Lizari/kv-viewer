# CLAUDE.md

## プロジェクト概要

このプロジェクトは、**CSV または手入力で与えたデータをもとに、一覧画面または単票画面の表示結果を簡易プレビューするツール**を実装するためのものです。

目的は、単体テストのように「このデータを入れると、画面ではこう表示される」を素早く確認できるようにすることです。  
特に、**コード値変換後の表示内容**を視覚的に把握しやすくすることを重視します。

このツールは **実 DB を使いません**。  
あくまで **ローカルな入力データ + 表示定義 + コード変換定義** によって表示結果をシミュレーションするツールです。

なお、Vite+ は導入時点で Alpha 段階のため、実装では過度に Vite+ 固有機能へ依存せず、React + TypeScript のアプリ本体は標準的な構成を保つことを推奨します。

---

## 技術スタック

このプロジェクトの v1 は以下の技術スタックを前提とします。

- **React**: UI 実装
- **TypeScript**: 型安全な実装
- **Vite+**: 統合ツールチェイン（開発 / ビルド / チェック / テスト / 実行の入口）
- **pnpm**: 基本のパッケージマネージャー / ワークスペース管理

### 技術スタック方針
- フロントエンドのみで完結する構成を優先する
- UI は React の関数コンポーネントを基本とする
- ローカル状態管理で完結できる範囲は、過剰な状態管理ライブラリを導入しない
- ファイル読込（CSV / JSON）はブラウザ上で処理する
- ビルド / 開発環境は Vite+ + pnpm を前提にする
- 日常の実行コマンドは `vp` を優先し、依存関係とワークスペース管理は pnpm 前提で整理する

### Vite+ / pnpm の運用方針
- Vite+ は統合ツールチェインとして採用し、`vp dev`, `vp build`, `vp check`, `vp test` を基本コマンドとする
- pnpm は依存関係管理とワークスペースの基盤として採用する
- `packageManager` や lockfile は pnpm ベースで管理する
- Claude は新規コマンド提案時、まず `vp` で表現できるかを確認し、必要に応じて pnpm コマンドを補助的に使う

### 依存方針
- まずは標準 API と最小限のライブラリで実装する
- CSV 解析やバリデーションが必要な場合のみ、用途が明確な軽量ライブラリを導入する
- UI ライブラリは必須ではない。MVP では素の HTML テーブル + 最小限のスタイルでよい

## このプロジェクトで重視すること

- 実 DB 接続はしない
- まずは **MVP を小さく確実に作る**
- 複雑な画面再現ではなく、**簡易プレビュー**を優先する
- 画面専用の固定実装ではなく、**定義駆動**で使い回せる形にする
- ユーザーが扱うデータは **1 テーブル相当のフラット構造**
- 複数テーブル結合が必要な場合は、ユーザー側で結合済み CSV を用意する前提

## 想定ユーザー価値

このツールで以下をすぐ確認できるようにすること。

- この入力データなら画面ではどう表示されるか
- コード値変換後に何が表示されるか
- 元データと表示結果の差異
- 未定義コードやデータ不足

## 基本設計方針

このツールは以下の 3 要素を分離して扱います。

1. **入力データ**
   - CSV または手入力で与える元データ

2. **画面定義**
   - どの項目を、どのラベルで、どの順番で表示するかを定義するもの
   - 画面上で編集可能
   - JSON 形式で保存 / 読込可能

3. **コード変換定義**
   - コード値を表示用ラベルへ変換するための定義
   - CSV 形式で管理する

---

## データ仕様

### 1. 入力データ CSV

- 1 列 = 1 項目
- 1 行 = 1 レコード
- フラット構造を前提とする
- 一覧は複数行を扱う
- 単票は 1 件を扱う

例:

```csv
user_id,user_name,status_cd,gender_cd
U001,山田太郎,1,1
U002,佐藤花子,2,2
```

### 2. コード変換 CSV

- `code_type` ごとに変換辞書を構築する
- `code_value` を `code_label` に変換する

例:

```csv
code_type,code_value,code_label
status_cd,1,申請中
status_cd,2,承認済
status_cd,9,取消
gender_cd,1,男性
gender_cd,2,女性
```

### 3. 画面定義 JSON

v1 の正式形は以下です。

```json
{
  "version": "1.0",
  "screenName": "ユーザー一覧",
  "screenType": "list",
  "fields": [
    {
      "sourceField": "user_id",
      "label": "ユーザーID",
      "order": 1,
      "visible": true
    },
    {
      "sourceField": "user_name",
      "label": "氏名",
      "order": 2,
      "visible": true
    },
    {
      "sourceField": "status_cd",
      "label": "ステータス",
      "order": 3,
      "visible": true,
      "converter": "status_cd"
    }
  ]
}
```

#### ルート項目
- `version`: 定義フォーマットのバージョン
- `screenName`: 画面定義名
- `screenType`: `list` または `detail`
- `fields`: 表示項目定義の配列

#### fields の項目
- `sourceField`: 入力データ上の項目名
- `label`: 画面上の表示ラベル
- `order`: 表示順
- `visible`: 表示可否
- `converter`: コード変換名。不要なら省略可

---

## 画面種別の仕様

### 一覧画面 (`screenType: list`)
- テーブル形式で表示する
- 列は `fields` に定義された順で表示する
- `visible: true` の項目のみ表示する
- `converter` が指定されていれば変換後の値を表示する

### 単票画面 (`screenType: detail`)
- 2 列テーブル形式で表示する
- 左列: 項目名
- 右列: 表示値
- `visible: true` の項目のみ表示する
- `converter` が指定されていれば変換後の値を表示する

---

## 必須機能要件

### 1. データ投入
- CSV をアップロードできること
- 手入力でデータを編集できること
- 一覧用は複数行データに対応すること
- 単票用は 1 件データに対応すること

### 2. 画面定義編集
- 画面上で画面定義を新規作成 / 編集できること
- 設定した内容を JSON としてエクスポートできること
- JSON をインポートして再利用できること

### 3. コード変換
- コード変換 CSV を読み込めること
- `converter` 指定がある場合、対象の入力値を表示ラベルへ変換できること
- 未定義コードの場合は警告できること

### 4. プレビュー
- 一覧画面のプレビューを表示できること
- 単票画面のプレビューを表示できること
- 元データと表示結果の違いが分かること

### 5. 警告表示
- 未定義コードを警告表示すること
- `sourceField` が入力データに存在しない場合は警告すること
- 空値の扱いは明示すること（空文字のまま表示、または空欄表示）

## 推奨アーキテクチャ

このツールは **フロントエンドのみで完結する構成** を第一候補とします。  
ローカルで完結する方がシンプルで、実 DB 不要という要件とも合います。

### 優先構成
- React
- TypeScript
- Vite+
- pnpm
- ローカル状態管理（必要最小限）
- ファイル読込はブラウザ上で実施

### 理由
- CSV / JSON の読込が容易
- 表示プレビュー中心でサーバー必須ではない
- React + TypeScript で UI と型定義を整理しやすい
- Vite+ により開発・ビルド・チェックの導線を統一しやすい
- pnpm により依存管理とワークスペース管理をシンプルに保ちやすい

ただし、既存リポジトリの技術スタックが決まっている場合は、**既存方針を優先**してください。

## 変換ロジックの方針

### 基本ルール
- `converter` が未指定なら元値をそのまま表示
- `converter` が指定されている場合は、コード変換 CSV から一致する `code_type` を探す
- 一致する `code_value` が見つかれば `code_label` を表示
- 見つからなければ元値を残しつつ警告する

### 例
- `status_cd = 1`
- `converter = "status_cd"`
- 変換定義に `status_cd,1,申請中` があれば表示は `申請中`

---

## バリデーション方針

以下は最低限チェックすること。

### 画面定義 JSON
- `version` が存在する
- `screenName` が空でない
- `screenType` は `list` または `detail`
- `fields` が配列である
- 各 `field` に `sourceField`, `label`, `order`, `visible` がある
- `order` は重複してもよいが、表示時は昇順で並べる
- `visible` は boolean

### 入力データ
- ヘッダ行がある
- 単票画面で複数行入力された場合の扱いを明示する
  - v1 では先頭行のみ採用でもよい
- `sourceField` に対応する列がない場合は警告

### コード変換 CSV
- `code_type`, `code_value`, `code_label` 列が存在する
- 同一 `code_type + code_value` の重複があれば警告

---

## エラーハンドリング方針

以下は無視せず、UI 上で分かる形で表示すること。

- 不正な JSON
- 不正な CSV
- 必須列不足
- 未定義コード
- 画面定義に存在する `sourceField` が入力データに存在しない
- 単票なのにデータが 0 件

エラーで全停止するよりも、**可能な範囲でプレビューを継続しつつ警告する** 方針を優先してください。

---

## テスト観点

実装時は少なくとも以下を確認してください。

### 正常系
- 一覧画面の CSV を正しくプレビューできる
- 単票画面のデータを正しくプレビューできる
- コード変換が適用される
- `visible: false` の項目が非表示になる
- `order` 順に並ぶ
- JSON のインポート / エクスポートが往復可能

### 異常系 / 境界系
- 未定義コードが警告される
- `sourceField` 不足が警告される
- 空値が扱える
- 単票で複数行データが入ったときの挙動が一貫している
- コード変換 CSV の重複定義が警告される
- 不正 JSON / 不正 CSV で適切にメッセージが出る

## 受け入れ条件（MVP）

以下を満たしたら MVP 完了とみなします。

1. CSV で入力データを読める
2. 手入力でもデータを扱える
3. コード変換 CSV を読める
4. 画面定義を画面上で作成 / 編集できる
5. 画面定義を JSON として保存 / 読込できる
6. 一覧画面をテーブル表示できる
7. 単票画面を 2 列テーブルで表示できる
8. 未定義コードや不足項目を警告表示できる

## 推奨ディレクトリ方針

React + Vite+ + TypeScript + pnpm 前提で、少なくとも以下の責務分離を意識してください。

- `components/`: プレビュー表示やフォームなどの UI コンポーネント
- `features/`: 画面定義編集、CSV 読込、プレビュー生成などの機能単位
- `types/`: `ScreenDefinition`, `FieldDefinition` などの型定義
- `utils/` または `lib/`: CSV 解析、変換処理、バリデーション

構成は既存コードに寄せてよいですが、**表示ロジック・定義読込・変換ロジック** は分離してください。

## 実装上の注意

- 過剰な抽象化は避ける
- まずは v1 の要件に集中する
- 複数テーブルや複雑な条件分岐を先取りしない
- データ・画面定義・変換定義を混ぜない
- 表示ロジックとファイル読込ロジックを分離する
- UI の見た目より、表示結果の正しさを優先する
